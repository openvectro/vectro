# The .riv format, as Vectro reads it

Vectro writes `.riv` so that every file it exports plays on Rive's free, MIT-licensed
runtimes (web, Flutter, iOS, Android) from day one. This page records what we have
confirmed by reading real files with `riv-dump`, not what we assume.

Sources: Rive's published format page (rive.app/docs/runtimes/advanced-topic/format) and
the generated headers in rive-app/rive-runtime (MIT). The closed Rive editor is never
decompiled; Rive.app is used only to export test files and to open ours.

## Layout

| Part | Encoding |
|---|---|
| Fingerprint | 4 bytes, `RIVE` |
| Major version | varuint (LEB128). Must equal 7; majors do not read each other |
| Minor version | varuint. Newer minors add features; unknown ones are no-ops |
| File id | varuint |
| Table of contents | varuint property keys ending in 0, then 2 bits per key packed into little-endian u32 words: 0 uint/bool, 1 string, 2 float, 3 color |
| Objects, to end of file | varuint type key, then (varuint property key, value)*, then 0 |

Values: uint and id are varuint; int is zigzag varuint; double is f32; color is u32;
bool is one byte; string and bytes are varuint length plus bytes. The table of contents
lists only properties newer than major 7, so a reader can skip what it does not know.

Objects have no nesting in the stream. Hierarchy comes from `parentId`, an index into
the current artboard's components; animations, keyed objects and keyframes follow
their owner in order.

## The schema

`data/rive-keys.json` holds 360 object types and 666 properties, generated by
`tools/extract_rive_keys.py` from the runtime headers. Regenerate it when Rive ships a
new minor version.

## What a real file holds

`seller.riv` (4.9 KB, format 7.0) decodes to 502 objects:

- 1 artboard (1000 x 1000) holding a boned character: 6 root bones, 5 tendons, 5 weights, 6 shapes built from 7 paths
- 8 linear animations, 40 keyed objects, 104 keyed properties, 220 keyframes, 10 cubic easings
- 1 state machine: 2 layers, 8 animation states, 11 transitions, 3 bool inputs, 6 conditions

Vector geometry is stored as vertices with in/out handles in polar form (rotation,
distance). The head is a circle of radius 57.27 drawn with four cubic vertices whose
handles are 31.63 long: the standard 0.5523 circle ratio, which confirms the decode.

All five sample files read to the last byte (502 to 850 objects each).
